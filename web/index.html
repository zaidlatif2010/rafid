Fidelity test: how far routing moves the model from the exact one

Takes the answers written with routing off in your earlier tests, and has each routing mode read them token by token while routing, as it does when writing. At every token it measures: would it have chosen the same token as the exact model? And how far is its prediction from the exact model's? It measures every token, not just the final answer, so it is far more precise than counting correct answers.

Modes (“off” is read first, as the reference)

Fidelity results

Same choice as the exact model, per conversation

  • Same choice: out of every 100 tokens, how many the mode would choose exactly as the exact model does. The first different token changes the answer from there on, but not necessarily its correctness.
  • Distance: how far the mode's prediction is from the exact model's, per token (KL in nats). Zero means the same prediction.
  • Tokens clearly apart: tokens whose distance is over 0.1, where the mode clearly “thought” something else.
  • Text difficulty: how much harder the exact model's answer became for the mode to predict (perplexity), compared with the exact model.
  • Routing depends on which experts have arrived from the disk at that moment, so repeating the test gives close but not identical numbers.

    The real measurement: experts from the disk
    
        
    Runs the model several times with different sizes of expert cache in RAM, really reading every missing expert from the disk, then compares the real speed with what the simulation expects from your fingerprint.
